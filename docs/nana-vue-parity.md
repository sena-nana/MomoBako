# Nana 与 Vue 对照

原生壳层以 Vue 界面为参照，但目标是正确，不是逐像素复刻。取舍的优先级：

1. 功能、数据和状态正确：设置真正生效，交互结果正确，空、错、禁用、加载各状态都对。
2. 符合 `DESIGN.md` 的设计意图，并沿用 Vue 的结构层级和文案。
3. 像素细节。

Vue 的缺陷、死代码和意外的层叠效果不照抄，按设计意图实现，并记在本页。

Vue 前端、Tauri 外壳和插件前端已经删掉（见 [迁移边界](./nana-migration.md)）。本页提到的 Vue、Tauri 和插件前端文件都在提交 `7bc847c` 里；要重新出 Vue 截图，在这个提交的 worktree 里起对照环境。现有的 Vue 截图留在本机的 `tmp/vue-mock/shots/`。

## 对照方法

- Vue 侧在本机的 `tmp/vue-mock`（`tmp/` 被 git 忽略，不在仓库里）：用 `@tauri-apps/api/mocks` 模拟 IPC，渲染 `src/` 的真实页面，在无头 Edge（与 WebView2 同内核）里截图。先在仓库根目录用 `yarn vite --config tmp/vue-mock/vite.config.ts` 起 Vite（端口 1420），再用 `bash tmp/vue-mock/shoot.sh <场景> [light|dark] [宽] [高]` 截一张，`shoot_all.sh` 批量截浅色、深色和 1200×800、960×600，图在 `tmp/vue-mock/shots/`。场景登记在 `tmp/vue-mock/scenes/*.ts`，夹具在 `fixtures.ts`，命令应答在 `ipc.ts`。
- 截图要经 DevTools 协议在导航前定好视口（`shoot.sh` 调 `shoot_cdp.mjs`），等满 12 秒再截（任务进度要爬到 88）。只给 `--window-size` 时，无头 Edge 在加载期间的视口是 1170×705，截图前一刻才改成 1200×800：CSS 布局会跟着重排，可打开时按视口算一次位置的右键菜单、任务弹层会按 705 高夹住，看起来像 Nana 的位置不对。
- Nana 侧用 `scene_shots` 按场景名出图和节点清单，命令和输出位置见 [离屏验收证据](./nana-offscreen-evidence.md)。场景定义在 `src-nana/src/shell/acceptance_*.rs`，和 Vue 场景同名。截图前先把视图量到尺寸后发回的消息（播放条宽、文件列表宽）归约几轮，截到的是稳定后的画面。
- 有仓库的场景从 `acceptance_base.rs` 的共用底子起步，对应 Vue 夹具 `base()`：照产品启动依次送回资源库列表、同步、仓库摘要、首屏目录和侧栏的读取结果，侧栏计数、目录树和文件列表都由这些结果算出。场景要别的条目、目录树、播放集、播放器或仓库时改底子的字段，和 Vue 场景改 `scene.entries`、`scene.playlists` 一样。缺失仓库的 `missing` 场景不用底子，直接送一条缺失的资源库。
- `python tmp/vue-mock/compare.py <场景>` 出单个场景的并排图、差异热图和差异像素比例，`report.py` 对两边同名的截图批量出对照页。比例只用来发现问题，不作为通过标准。

## 全局取舍

**颜色合成。**
- NanaUI 在线性空间混合（见 NanaUI `docs/reference/text-engine.md`），Chromium 在 sRGB 空间混合。带透明度的主题角色（强调浅底、悬停底、浅红浅绿底）在 Nana 里更亮，深色主题下更明显。主题角色保留 NanaUI 的设计，不为对齐改动。
- 例外：Vue 用整块 `opacity` 盖在已知不透明底色上的地方（禁用态、色块外圈、播放条淡化），改用 `SemanticColorMix::new(前景, 底色, 比例)` 直接在 sRGB 通道混。
- 停用的图标按钮：NanaUI 的 `IconButton` 只给按种类配色的按钮停用时整枚淡到 50%（线性空间合成）；`colors_from_style` 的按钮照自己写的 `style.interaction.disabled` 画、不再淡（`cfc484ac7`）。壳层里会停用的图标按钮都是后一种，按上一条在 sRGB 里混好停用色，节点不透明度为空（`disabled_fade_tests.rs`）：
  - 侧栏四个标题工具、播放集行上的「播放」和添加资源库表单的关闭钮：弱色和 `--bg-elev` 按 0.45 混（`theme_map::disabled_paint`）。播放集行选中时底下是一层 `--accent-soft`，停用的「播放」仍按侧栏底色混，没有 Vue 透出来的那一点强调色。
  - 对话框的关闭位（导出对话框）：也改成 `colors_from_style`，平时是 Vue 的弱色叉号（按种类配色会被换成次要文字色），导出中按卡片底色混。
  - 播放条的传输按钮：挂自绘的 `IconButton`，自绘不调 `draw_default`，按 `PaintState::disabled` 和卡片底色混。
  - 标题栏的侧栏开关和 Vue 一样从不停用。
- 纯黑遮罩：线性空间里是把底色乘以 `1 - α`。要和 Vue 的 45% 黑一样暗，不透明度取 `linear_scrim_alpha(0.45) = 1 - 0.55^2.2 ≈ 0.732`。对话框的遮罩是主题的效果令牌 `modal_scrim`，`appearance.rs` 按这个换算写进去；背景模糊是 `modal_scrim_blur`，照 CSS 写 2。

**按钮。**
- Lilia 全局样式 `input, button, select { height: 32px }` 会压过组件自己声明的尺寸，例如 26px 的筛选芯片、日志芯片、适应/填充分段，以及 24px 的分组标题按钮。这种情况视为层叠缺陷，按组件声明的设计值画。没有声明尺寸的普通按钮和下拉照 32px 画。
- 侧栏行按声明的 28px 画（Vue 实际渲染为 32px），所以下面各组比 Vue 上移约 20px。
- 只写了裸类名、在 `src/styles` 里没有任何样式的按钮（`primary`、`ghost`、`ghost danger` 等），Vue 渲染成透明底、正文色。Nana 按 DESIGN.md 5.1 画：主操作用低饱和强调色，危险操作用低饱和红，普通操作透明。

**圆角。**
- 圆角半径基数来自设置（0–20，默认 8）。xs 到 2xl 分别是基数的 0.5、0.75、1、1.25、1.5、2 倍（`theme_map::corner_metrics`），2xl 是主题的 `RadiusTier::Xxl`。
- Vue 用 `--radius-2xl` 的大块表面都写 2xl 档：文件卡和详情卡、预览页、播放条、播放集面板，以及插件、日志和搜索页的工作台面板（`.search-workbench__panel`）。改了圆角半径重新装主题，这些表面跟着变，不用重建。
- 「平滑」圆角是主题的 `CornerShape::SQUIRCLE`（CSS `superellipse(2)`），「普通」是圆弧。

**滚动条。**
- 照 Vue 的全局 overlay 滚动条（`src/composables/useGlobalScrollbarVisibility.ts`，样式在 Lilia `global-scrollbar.css`，最早写在 `2c6b17b` 的 `index.css`）：原生滚动条隐藏、不占宽度；指针到滚动区上、滚动或拖动时淡入一条 4px 的 `--border-strong` 胶囊，没有轨道，悬停和拖动都不换色、不变粗，最短 24px；理由都没了以后停 480ms 再按 `transition: opacity .48s ease` 淡出。Vue 现在看不到这条滚动条，是缺陷，见下文「没照抄的 Vue 缺陷」。
- 写在主题里，所有滚动区跟随，不逐个写（`appearance.rs`）：尺寸是 `ThemeMetrics::scrollbar`（12px 车道贴着滚动区的边、不内缩，4px 滑块，激活时也是 4px），颜色、动效和显隐策略是 `ScrollbarRecipe`（`AutoHide`；三态滑块都是 `--border-strong`，没有轨道；淡入淡出 480ms CSS `ease`，停 480ms）。
- 滚动条叠在内容上，画在滚动区所有后代之上（NanaUI `7f94c925d`），不占布局。56 个场景升级前后的截图只有停用图标按钮的颜色变了，内容宽度、网格列数和列表右边距都没有变化；换上这份尺寸和配方前后，截图和节点清单逐张相同。静止时滚动条不显示，截图里也没有滚动条；指针停在滚动区上时的样子由 `live_visual` 的 `hovered_settings_page_paints_the_overlay_thumb` 在真像素里查。
- 和 Vue 设计的差别：Vue 只在指针进到滚动区右边（底边）12px 以内时浮出，Nana 指针进到滚动区就显示（NanaUI 的 `AutoHide` 没有只认边缘的模式，见下文「NanaUI 缺口」）；NanaUI 把滑块放在车道正中，竖条离右边 4px（Vue 贴边）、横条离底边 4px（和 Vue 一样），两端不留空（Vue 各留 4px）；滑块在滚动区自己的层叠上下文里，后面的兄弟节点和视口固定的浮层仍能盖住它，Vue 的滑块是 `z-index` 最高的固定定位浮层。

**关闭窗口。** 和 Vue/Tauri 一样直接退出，只有存在未保存修改时才先确认。

## 没照抄的 Vue 缺陷

### 壳层与侧栏
- 文件面板收的是全局 `error`：任何失败（定位失败、读素材详情失败、刷新文件夹树失败……）都把文件列表换成红色状态框，和侧栏状态区重复，列表也看不到了。Nana 的文件列表只显示文件区自己的失败（自己发起的目录读取和文件变更），别的失败只在侧栏状态区。
- 删除资源库、删除文件夹的选项卡片被全局 32px 高度压扁，标题和说明叠在一起。
- 智能文件夹对话框的最大高度是 72vh，800 高的窗口下底部「取消 / 创建」被裁掉。
- 启动日志时间用了未定义的 `--text-subtle`。
- 文件夹树的展开箭头底色盖住了树的引导线。
- 资源库切换按钮的无障碍名只有「资源库」，不含仓库名。
- 添加菜单的 160px 宽被 `.ctx-menu` 的最小宽度覆盖。
- 刷新文件夹树途中换了仓库，Vue 后半段的重读按当时的活动仓库读，会落到新仓库上；Nana 作废这一轮。
- 换仓库时 Vue 不改当前面板：在回收站、智能文件夹或播放集面板上换仓库，面板留着，回收站面板接着显示新仓库的根目录（不是回收站），智能文件夹和播放集面板是空的。Nana 换仓库时这三个面板回到文件面板。
- 看不到滚动条：原生滚动条被 Lilia 隐藏（`* { scrollbar-width: none }`、`::-webkit-scrollbar { width: 0 }`），本来由 overlay 滚动条代替。切到 LiliaUI（`613fa7d`）以后它的样式挪进了 Lilia 的 `global-scrollbar.css`，只有 Lilia 自己的 `installGlobalScrollbarVisibility` 会加载这份样式，MomoBako 调的是 `src/composables` 里自己那份旧实现，不加载。滚动和悬停边缘时浮层照样建出来、带上 `is-visible`，但没有定位和颜色：在 `tmp/vue-mock` 里滚动日志页，浮层的 `position` 是 `static`，`::before` 的 `content` 是 `none`、底色透明。所以 Vue 任何时候都看不到滚动条，也没法拖。Nana 按上文「滚动条」的设计意图画。

### 文件页
- 导入菜单用了未定义的 `--panel-bg`，退回到 `#15171a` 深色底，字看不清。
- 960×600 下面包屑「根目录」逐字竖排，分隔线压到卡片上。
- `.files-list` 的网格行被拉伸或挤压。
- 详情预览是透明底白图标，浅色主题下看不见。
- 文件卡 `overflow: hidden` 把导入菜单裁掉。
- 导出对话框缺少输出路径，已补上。
- 列表模式在 960 宽下标题列被压到 0、内容溢出卡片；Nana 给标题至少留 80px。
- 右键子菜单离分组 4px，中间是父菜单的内边距，不属于 `.ctx-menu__slot`：指针慢慢移过去时 `:hover` 断一下，子菜单闪关。Nana 的子菜单连同这 4px 接缝整块接住指针，在分组和子菜单之间、子菜单里移动都不收起。
- 回收站里的「缩略图」分组是禁用的，但 `.ctx-menu__slot:hover` 不看按钮禁用，悬停照样弹出子菜单，里面的项还能点。Nana 禁用的分组不展开。
- 「刷新缩略图」照 Vue 调 `ensureThumbnail` 的 `refresh`，但后端原来的 `refresh` 有三处会丢图，改在后端（`api-design.md` 的 `thumbnails:ensure`），Vue 和 Nana 共用：文件夹的刷新直接删掉自定义缩略图，和「取消自定义」一样；有自定义缩略图的文件刷新以后交回生成的图、标成不是自定义，重读目录又变回自定义的那张；没有生成器的类型（PDF、Office、文本、模型，缩略图是 Vue 的插件生成的）和重新生成失败时把原来的缩略图清掉。现在刷新只换能重新生成的那张，自定义的一直留着，不支持的类型原样留着，失败报错、旧图留着。
- 从仓库切换列表换仓库时，Vue 等 `selectRepository` 整个跑完才关弹层（`selectRepositoryFromList` 的 `.then`），侧栏收起、回到启动页以后，切换弹层还一直浮在启动页左上角（`repo-switch-startup`）。Nana 一选就关。
- 来源条目动作的 operation：插件 SDK 只约定了五种（`SourceEntryActionOperation`，`docs/api-design.md` 写明是固定的几种、声明不能让宿主执行别的命令），随附插件（网易云音乐）也只声明这五种。Vue `actionsForDeclaration` 的最后一个分支把约定以外的值一律当成「创建播放列表」：不看声明的 method，拿单曲也会建播放集。Nana 原来对约定以外、写了 method 的声明直接调用这个插件方法，同样越出约定、宿主也不知道该出什么进度和刷新。现在约定以外的声明不出菜单、只记日志；没写 scope 的声明也不出（Vue 要求 scope 和条目类型相同，Nana 原来对所有条目都出）。
- 来源条目的标识：Vue `sourceNumber(entry, key)` 在来源载荷和元数据都没有这个键时退回条目的 `providerItemId`（条目在来源里的标识，网易云的单曲是歌曲标识、歌单目录是歌单标识，`catalog.rs` 的 `track_entry` / `folder_entry`），但不分键：单曲没有 `playlistId` 时也填成歌曲的标识，歌单目录没有 `songId` 时也填成歌单的标识，插件会拿错的标识去取。Nana 原来完全不退回，第三方来源的条目没有这两个键时载荷就缺 `songId` / `playlistId`。现在按条目种类只退回对应的那个：文件（单曲）的 `songId`、目录（歌单目录）的 `playlistId`；老载荷没写条目种类时，照 Vue 用同一个标识认单曲和歌单目录。「创建播放列表」的歌单标识照 Vue 在不是数字时原样用目录的来源标识，空白的不算（Vue 也报「来源目录缺少播放列表标识」）。
- 来源目录的「创建播放列表」失败时（缺歌单标识、建播放集或加入条目出错），`selectContextMenuItem` 只 `await item.onSelect()`，异常没人接，界面上什么都不显示。Nana 照 `runPlaylistAction` 在本地建播放集，失败写进文件列表的错误。
- 来源条目动作在来源认证或本地缓存不可用时（Vue `actionDisabled`）禁用，原因「来源认证或本地缓存不可用」放在 `confirmLabel` 里；`confirmLabel` 要点一次没禁用的项才显示，禁用的按钮点不了，原因从来显示不出来。Nana 禁用这些项，紧跟着一行弱色小字写出原因（同一个原因只写一行）。
- 「下载到其他资源库」没有候选（没有别的就绪、可写资源库）时，Vue 照样能点，点了什么也不发生（`openDialog` 返回 null）。Nana 在菜单上禁用这一项，写「没有可下载到的其他资源库」；点的那一刻候选没了（列表刚换过）写进文件列的错误。
- 来源下载有部分失败时（网易云下载歌单逐首下载，失败的放进结果的 `failed`，整个调用照样成功），Vue 只在任务行写「下载完成，N 项失败」，可紧接着的 `context.refreshRepo()` 开始「加载资源库」、占住任务行，这句话从来看不到，失败的条目只打在控制台；插件自己写的失败日志宿主原来也不收（`mutsuki_host::call_session` 只取调用的输出，插件事件整个丢掉，调用失败时 SDK 也不带回）。Nana 把失败的条数写进侧栏状态区（「下载歌单「夜曲」有 2 项失败，原因见「日志」。」），每一条的名称和原因写进系统日志（宿主来源，分类 `source`、动作 `downloadItemFailed`，记在来源资源库和插件名下）。收尾的刷新不清这条提示，用户开始下一个操作时照常清掉；全部成功时不提示。
- 插件经 SDK 写的日志现在由宿主写进系统日志（`plugin_events.rs`，调用失败时也带回，见 `api-design.md`），Vue 和 Nana 共用。修好以后有两处会和宿主已有的记录重复，都留宿主一侧、删掉插件一侧：
  - 歌单里逐首的下载失败：网易云插件原来另写一条 `playlistTrackDownloadFailed`（只有歌曲标识和原因），和 Nana 的 `downloadItemFailed` 重复。留 Nana 的：状态区那句「原因见「日志」」是宿主的承诺，换成别的来源插件（不写日志的第三方插件）也要兑现，只有宿主按结果的 `failed` 逐条写才保得住；宿主这条还带动作名、歌单名、歌名，记在来源资源库名下，插件不知道动作名。代价是 Vue 收不到逐首的失败日志，和原来一样。
  - 调用失败：网易云插件原来在每次调用失败时写 `sourceCallFailed`（方法和原因），宿主对所有插件统一写的 `callFailed` 是同样的内容，删掉插件的。
- 歌单下载到其他资源库时，Vue 把文件导入到以歌单命名的文件夹（`parentPath = playlistName`），可目标资源库里没有这个文件夹，导入报「directory not found」，异常没人接。Nana 导入前在目标资源库建这个文件夹（名字里的路径分隔符换成「_」），再导入、同步。
- 下载到其他资源库时目标资源库里已有同名文件：Vue 的导入（后端 `validate_external_import_entries`）遇到一个同名就整批报「entry already exists」，异常没人接，重复下载同一个歌单时新下的文件一个也进不去，界面上什么也没有。Nana 导入时带 `skipExisting`（`files:import`，见 `api-design.md`）：已有的同名文件保留原文件、不导入，其余照常导入；状态区写「…目标资源库「{名称}」已有 N 个同名文件，保留原文件、没有导入。」（只有跳过时是提醒，有失败的条目时并进失败那一句），跳过的路径写进系统日志。做法和后端已有的外部素材接入（`add_external_assets`）一致：同名的条目逐条报出、照常导入其余的，不覆盖；也不改名另存，免得重复下载堆出副本。复制、移动和用户自己发起的导入（拖放、导入对话框）照旧整批拒绝。
- 下载到其他资源库的暂存文件：插件先下到来源缓存目录的 `.momo/cache/download-staging/{目标资源库}`，宿主导入目标资源库以后这些文件一直留着，导入时跳过的同名文件也留着，越下越多（Vue 和 Nana 原来都这样；插件按目标资源库共用一个暂存目录，再下同一首会覆盖上次暂存的）。现在 Nana 管暂存目录：每次下载新建一个空目录，作为 `destination.stagingPath` 交给插件（插件写在里面、不覆盖），导入完成（包括跳过）以后只删交回的、在这个目录里的文件和变空的文件夹，别处的东西一个也不删；导入失败时文件留着，位置写进日志。约定见 `api-design.md`。Vue 不传 `stagingPath`，插件照旧放进共用的暂存目录，没有人清。
- 下载到本地时用户选的目录里已有同名文件：网易云插件原来先删掉已有文件再放下新下载的（歌词直接覆盖写），Vue 和 Nana 都一样，没有任何提示，用户目录里的文件被悄悄换掉。插件是两边共用的，现在改成只新建、不覆盖：已有的同名文件保留原样、不写入（音频已经在就不再下载），结果的 `skippedEntries` 报出保留了哪些（`api-design.md` 的来源下载结果约定）；同一次下载里两首歌渲染出同一个文件名时，后来的照虚拟目录的命名加 ` [歌曲标识]`，不会把自己前一首当成已有文件。Nana 照下载到其他资源库的样子在状态区写「…：下载目录里已有 N 个同名文件，保留原文件、没有写入。」（只有保留时是提醒，有失败的条目时并进失败那一句），保留的路径写一条警告日志；Vue 不读这个字段，只是不再覆盖。
- 「选择目标资源库」的候选是 `<button>`，被全局 `input, button, select { height: 32px }` 压扁，`overflow: hidden` 的名称和路径被挤到约 1px 高，候选只剩两块空白；悬停描边用了没有定义的 `--accent-weak`。Nana 按内容高画卡片，悬停描强调色。
- 元数据里来源链接的「打开链接」：Vue（`isOpenableSourceLink`）对除 `javascript:`、`data:`、`vbscript:` 以外的任何协议都可以点，可 Tauri opener 的默认范围只放行 `http`、`https`、`mailto`、`tel`，其余协议点了会失败，而且界面上没有任何反馈；`C:\…` 这样的盘符路径也会被当成协议。Nana 只对这四种协议启用按钮，归约里也会再拦一次（`host_api::openable_url`）。

### 搜索与筛选
- 筛选芯片按设计值 26px 画；结果行高度按内容决定。
- 高级区的宽输入框填满格子（Vue 卡在 120px 宽，占位文字被截断）。
- 占位文字用弱化色（Vue 是浏览器默认的 `#757575`）。
- 手动加的颜色和形状始终有芯片，可以单独点掉。
- 搜索失败时显示真实错误，不再叠一个「等待搜索条件」。
- 搜索跑完没有命中时，空状态写「没有匹配的文件」和所在范围（没有筛选条件时是全部资源库，有筛选条件时是当前资源库的名字）；Vue 仍写「等待搜索条件」。

### 预览与播放
- 唱片按视口定尺寸，在预览框里溢出、被裁成方块，歌词栏也被裁掉。
- 播放请求被暂停打断时，Vue 把它当错误显示。
- 文本按字节截断时切开半个字符，留下替换符。
- 压缩包预览用了未定义变量，浅色主题下也是深色面板。
- 播放条的宽排版网格在窄栏里溢出，断点只看窗口宽度：1200×800 的文件页（侧栏和右侧详情都在）里卡片只有 558 宽，Vue 照样排一行，按自己的栏宽下限（媒体 220、时间音量 170）把音量滑杆挤出卡片。Nana 在窗口不宽于 1120px，或者播放条自身窄于宽排版的下限时切换三行排版。下限按内容算：内边距 32、传输 188、两道栏距 36、时间音量 170、媒体 126（58 封面、12 间距和标题的四个字），再加两侧 1px 边，共 554；558 宽的卡片照 Vue 留在一行，标题按省略号收尾，文件列表不被三行排版挤矮。
- 播放集条目标题被全局按钮样式居中。
- 自动播放失败后，图标仍显示「暂停」。
- 在 ASMR 资源库里打开音频预览，文件工作台和预览页上下同时出现，工作台里的播放条还显示「未选择播放内容」；Nana 只显示预览页。
- 文件预览里的音视频失败（读不出、认不出格式、解码失败），Vue 只在播放条第二行写一行弱色小字，预览框里照旧是唱片舞台或黑底。Nana 照 Vue 预览插件（`audioPreview.js`、`media-preview`）的失败浮层，在预览框里写红色标题「无法预览该音频」（视频是「无法预览该媒体」），下面一行原因，包括 Nana 自己的「没有原生解码器」和各格式的「解码失败」。播放条装不上同一个文件、写回的失败也这样显示。预览和播放条共用同一个解码，坏的 wav、mp3、flac、ogg 报它自己格式的原因，不再被说成没有解码器。
- 新建播放集失败时 Vue 只留着对话框、没有任何提示（请求失败成了没人接的 Promise 拒绝），也没有处理中状态，可以重复提交。Nana 等结果回来再关对话框，处理中禁用按钮、不能关，失败把原因写在对话框里。

### 设置、插件与日志
- 日志追踪滚动的是 `.logs-workbench__list` 本身，但列表不定高（只有 `min-height: 360px`），实际不会滚动，记录一多页头和筛选就跟着整页滚走。Nana 照 Vue 的结构让页面主体（`.workspace-page__body`）和列表都能滚，再按意图给列表定高：面板至少撑满主体，列表在筛选下面分走剩下的高度、自己滚动，追踪时跟随末尾，暂停时停在原位；窗口放得下时主体不随列表里的日志滚动。
- 日志列表的最小高有意偏离 Vue 的 360，收到 72（`admin_logs_view::LIST_FLOOR`），为的是保证追踪状态下最新记录可见：照 360 的话 960×600 和 960×480 都放不下，追踪时最新一条落在主体可视区下面，要滚一下页面才看得到。现在列表在主体剩余的高度里伸缩，960×600、960×480 下主体不滚，列表跟到末尾时最新一条的消息就在可视区里（单行消息的卡片从消息行到底边约 70，960×480 下筛选以下还剩 74）；窗口矮到连 72 都放不下时主体才滚。1200×800 下列表本来就比 360 高，表现不变。
- 文件导入、Eagle 导入工具页的 `tool-page-shell` 类全仓库没有 CSS。
- 圆角滑杆用了 `appearance: none`，轨道不可见。
- 设置数据刷新成功后，旧的错误提示不会清掉；Nana 刷新成功会清掉。

## 已知差异

### 交互
- 右键子菜单照 Vue `.ctx-menu__slot:hover` / `:focus-within`：指针或键盘焦点进到分组那一行（含子菜单）就展开，都离开就收起，没有延迟；点分组不收起，按下时焦点落在分组上，指针移开也留着；Tab 进分组展开，再 Tab 走进子菜单。指针和焦点各在一个分组里时，Vue 两个子菜单叠着显示，Nana 只显示指针所在的那个。
- 键盘打开菜单（`menu_focus.rs`）：仓库头和文件页的「导入」是菜单按钮（`has_popup`，仓库头照 Vue 的 `aria-haspopup="menu"`），焦点在上面时 ArrowDown 打开菜单、焦点落在首项，ArrowUp 落在末项；文件卡片和侧栏文件夹行上的菜单键和 Shift+F10 打开右键菜单，焦点落在首项。切换列表、添加菜单、导入菜单、两种右键菜单和右键菜单的每个子菜单各是一个方向键焦点组，上下键在本层的项之间走、首尾相接，Enter 执行，带子菜单的分组照 Vue 报成菜单按钮，Tab 从分组走进子菜单。指针打开的菜单不动焦点。菜单关掉以后焦点去哪见下面的「焦点归还」。Vue 的这些菜单没有方向键，也不把焦点放进菜单。
- 文件夹行的右键菜单和文件右键菜单是同一份实现（`context_menu.rs`），外观照 `.ctx-menu`，键盘操作也一样；Vue 里两处也是同一个 `ContextMenuHost`。原来文件夹菜单是 NanaUI 的 `ContextMenu`，没经 `OverlayHost` 打开，方向键和 Enter 走不到它，菜单键也不开。Vue 的文件夹菜单只能右键打开。
- 菜单能用键盘打开以后，焦点可以从开着的菜单走回页面（菜单不困住焦点），再在仓库头上打开切换列表，这时两层同时开着：显示的是仓库弹层，Escape 也先关它、再关文件夹菜单（`escape_layer` 的先后和 `OverlayKey` 一致）。
- 所有对话框都响应 Escape、点外面和关闭位（处理中都不关）。Vue 手写的 `.modal-overlay` 对话框（删除资源库、文件夹、智能文件夹、播放集等）都不响应 Escape，只有删除插件用的 Lilia `ConfirmDialog` 响应；这里一致响应。
- 焦点归还（`focus_return.rs`，照 WAI-ARIA 对话框）：对话框打开时框架把焦点放进对话框（对话框本身，确认框是「取消」）。对话框、弹层和菜单关掉以后，焦点回到打开它的控件。打开它的是菜单项或弹层的上一页时，它们随菜单、弹层一起收起了，焦点回到菜单、弹层的主人：文件条目、文件夹行、仓库头、「导入」；右键菜单的主人总是那个条目或文件夹行，右键和菜单键打开的都一样。这个控件也不在了（删除确认以后目录树重读、列表换新，重命名以后条目换了键），就在它原来所在的那一片里找：从近到远第一层还在的容器里选中的项（当前文件夹、选中的文件条目），没有就取第一个能聚焦的控件，最远到侧栏或主区；整个区域藏着（换仓库时侧栏收起）就等它回来。自己弹出来、打开前没有焦点的硬链接确认关掉以后落在文件列表里选中的条目，没有时第一个条目；关闭确认打开前没有焦点时关掉以后也不放。菜单和弹层只在焦点本来就在里面时才还：指针打开、焦点留在别处的菜单关掉时不挪焦点。弹层换页时焦点跟进新的一页：添加菜单落在首项，后端表单落在第一个输入框。各对话框和弹层还到哪见 [壳层绑定式视图](./nana-shell-view.md) 的「焦点归还」。Vue 手写的对话框不管焦点，关掉以后焦点丢了；Lilia `ConfirmDialog` 有焦点陷阱，危险口气时先聚焦「取消」。
- 正在用输入法组合时，新的对话框等组合结束再打开（一激活就会拿走焦点、打断组合）。
- 同时打开的浮层只显示一层：关闭确认最先，其后是原来浮层槽位里的对话框、弹层和菜单，文件页的导出和文件对话框最后（原来画在主区里，压在浮层下面）。
- 点菜单外面关闭菜单时，这次点击不会穿透到下面的控件；右键别处只关菜单、不重新打开；滚动、缩放、失焦不会自动关菜单。
- 导入用应用内的路径对话框（Vue 用原生文件选择器）。
- 「定位」走 NanaUI `reveal_in_file_manager`：文件在所在文件夹里选中，和 Vue `revealItemInDir` 一样；文件夹是直接打开，Vue 是在上一级里选中它。插件设置目录的「打开目录」在 Vue 里是 `openPath` 打开目录，Nana 排的是定位，按上面的规则同样是打开。路径不存在时 Nana 报「定位失败：路径不存在」，不再让资源管理器打开默认文件夹。
- 框选只能选到已经建出来的卡片（视口加上下各 240px），选不到滚出视口很远的行。
- 瀑布流各列先按平均高度估算卡片高度，滚动中测到真实高度后，滚动条可能小幅跳动。
- 来源登录更新已有仓库以后，Vue 先 `refreshRepositoryWorkspace()`（读列表、把当前仓库原地同步一遍）再 `selectRepository(目标)`；Nana 合成一次：读列表，读完直接选目标仓库，不先同步当前仓库。
- 确认硬链接以后，Vue 等候选、仓库摘要和当前目录都重读完才放开确认框（`isMutatingFiles` 包着整轮刷新）；Nana 等重读的候选回来就放开（确认框显示的是这份新列表），摘要和当前目录在后台读，目录读回来之前文件列显示读取中、任务弹层是「读取目录」。确认以前发出、晚到的候选读取不认，不会把确认掉的那一条写回来。
- 任务弹层的仓库操作行：
  - 多选删除和还原在 Vue 里逐条调用，进度写「正在处理 {名称}」；Nana 一次协议处理完，写「准备处理 N 个条目」，等待时往上爬。
  - 下载歌单（`download-directory`）：Vue 先分页列出目录里的全部文件（`loadDirectoryFiles`，每页 500），把有 `songId` 的作为 `tracks` 交给插件，进度写「正在处理 N 个文件」。Nana 不列目录、不带 `tracks`，由插件按歌单标识取来源里完整的歌单（网易云插件 `playlist_tracks` 在 `tracks` 为空时取歌单详情里的全部 `trackIds`），进度和单曲一样写「准备下载 {名称}」→「正在下载 {名称}」。下载歌单要的是来源里的这个歌单，不是目录里此刻列出来的那几行：
    - 歌单目录是来源歌单的只读投影，用户在 MomoBako 里不能增删其中的曲目，列出来的行不带用户的取舍，只有歌单标识是用户的意图；
    - 列出来的不一定全、不一定新：网易云目录走分页回源并缓存 24 小时（`netease_directory_cache`）；插件的分页方法原来取歌单详情失败时返回空页、不报错，Vue 的循环就此结束，`tracks` 只剩前几页，插件只下这一部分，界面上看不出少了（现在报错，见下面「网易云插件吞掉错误」）；
    - 列目录本身很贵：插件每一页都从头取到这一页为止的歌曲详情，歌单越长越慢、越容易被限流，而插件按歌单标识取完整曲目表只要一次请求。
    - 不带 `tracks` 以后，失败的条目由插件用歌单详情里的歌名补上（详情没带到的歌按标识批量取一次歌曲详情），日志里写歌名；歌名实在取不到时才写「歌曲 {标识}」。插件交回的一批里一项也没有时，Nana 在状态区用警告色提醒「{动作名}「{名称}」没有下载到任何条目。」（`source_download.rs`），不再只有一闪而过的「下载完成」。
  - 网易云插件吞掉错误（插件两边共用）：下载歌单取不到歌单详情时什么也不下、照样交回成功；分页列目录（`filesystem.listDirectoryPage`）和不分页列歌单目录取不到歌单详情时交回空页、空目录。现在都报错，原因按种类写清楚：网络连不上或超时、登录失效（下载前先查一次登录状态，登录失效时网易云只给试听片段或者不给地址）、歌单不存在（接口 404 或返回里没有歌单）、请求太频繁、接口拒绝。宿主把插件交回的原因原样交给调用方（原来套着「plugin task failed: … {}」），Nana 的文件列写「{动作名}「{名称}」失败：{原因}」，列目录失败照常写在文件列。Vue 的下载失败没人接，界面上仍然什么也没有。
  - Vue 的爬升定时器会把更新到 88 以上的值压回 88（更新和完成总在同一拍，看不到）；Nana 不往回压。
  - 「同步资源库」「导入资源库」「配置网易云缓存」「导出资源库」在 Vue 里也有进度行，但入口函数（`syncActiveRepository`、`importExistingRepository`、`configureNeteaseRepositoryCacheInWorkspace`、`exportCurrentRepository`）没有界面调用方，Nana 不做。
- 过程中的状态（`tmp/vue-mock/scenes/states.ts` 和同名 Nana 场景）：
  - `file-operation-progress`（cover.png 拖进 assets，移动没回来）：两边都是「移动文件 · 移动到目标文件夹」爬到 88%、文件列「正在处理文件」、详情是 cover。「正在处理文件」两边都撑满列表宽：Vue 的 `.asset-browser__state` 写的是 `inline-flex`，但它是纵向 flex 容器的子项，照样被拉满，Nana 原来按字面画成随内容宽，已改。
  - `repo-switch-startup`（换到第二资源库，同步没回来）：两边都回到启动页、收起侧栏，停在第 2 步「扫描资源库文件」。加载日志的最近 8 条和明细两边一样（从「首屏启动流程完成。」到「首屏启动文件变化同步完成。」）；Vue 的日志时间是截图时的真实时钟，Nana 场景固定成 16:00:00。
  - `repo-refresh-sync`（刷新当前资源库，同步没回来）：两边侧栏状态区都是「正在同步仓库状态」，任务弹层都是「加载资源库 · 加载资源库摘要」的不定进度。状态行两边都撑满侧栏宽（`.workspace-state` 同样是纵向 flex 容器里的 `inline-flex`，Nana 原来随内容宽，已改）；不定进度的条两边都按 `progress-pulse` 呼吸（截图停在某一刻，透明度不同）。
  - `preview-no-player`（滤掉 media-preview 插件后预览 clip.avi）：两边播放条第一行「未选择播放内容」、第二行「没有可用于播放此媒体的插件」。预览框 Vue 是一块空白：视频总走播放器挂载点，没有播放插件时挂载点里什么也没有，用户看不出这里是什么。Nana 按文件类型画：视频画自己解出的画面（不靠播放插件，真窗口里是 AVI 的画面），还没有画面时（离屏会话没有宿主纹理，场景只交会话和音轨；或者只解出音轨）画缩略图或视频图标，是 DESIGN.md「明确的不可预览占位状态」，「能不能播」由播放条第二行说明。原来 Nana 按有没有画面分，没有画面的视频落进音频的唱片舞台、写「通用音频」「暂无歌词」，已改；准备卡也按文件类型写，视频是「准备媒体」（Vue `media-preview`），音频是「准备音频」。音频不会出这条提示：Nana 的内置解码器认领 mp3 这些格式，没有音频插件也接管播放条（见设置页「音频播放」的内置解码器）。
  - `files-multi-select`（单击 cover、Shift 单击 clip-01、Ctrl 单击 clip-03）：两边都是 cover、page、clip-01、clip-03 四项选中，详情「4 个项目 · 4 个文件」。1200×800 下两边的播放条都是一行，文件列表一样高，第二行卡片露出上半截；Nana 的标题在这个宽度按省略号收尾，音量在卡片里（见上文播放条的宽排版下限）。
  - 任务弹层的位置两边不同（`task-running` 也是）：Vue 按估算高度（至少 180）把弹层放在按钮上方，内容少时离按钮空一段；Nana 按实际高度贴着按钮上方。
- 计时按真实时间：动效、仓库操作行的爬升、搜索和自动保存的延时、文件夹悬停、缩略图预取、播放进度和图片停留，都按两帧之间真实流逝的时间走（`frame_clock.rs`），30 帧和 120 帧走到同样的状态。界面计时器和动效一帧最多算 250 ms：线程卡住或挂起后恢复时接着原来的位置走，不一下子跳到头（Vue 的 `setInterval` 卡住以后也只补一拍）；播放时钟不封顶，跟着系统设备上的声音走，图片幻灯片一帧最多切一项。播放中准备帧一直要帧，窗口最小化时进度和自动切项照常走。
- 刷新文件夹树要同步整个仓库。Vue 在整轮刷新期间把文件列表换成「正在读取目录」；Nana 在同步和重读期间照常显示列表，进度写在侧栏状态区，最后重读目录时列表才显示读取中。刷新按钮除了 Vue 的「正在读目录」，在目录树自己读取时也换成加载图标并禁用。实现见 [壳层绑定式视图](./nana-shell-view.md) 的「全局状态区」。

### 外观
- 侧栏、文件页和菜单的图标用 Tabler（Vue 用 Lucide），个别图形不同。预览、播放条、播放集页、设置、插件、日志和动作页把 Vue 用到的 lucide 源登记成产品图标（`player_icons.rs`、`admin_icons.rs`），形状和 Vue 一致。
- 对话框统一用 NanaUI `Dialog` / `ConfirmDialog`（行为优先）。距顶 12vh、最高 72vh、`--radius-xl`、三段内边距和两条分隔线、遮罩的暗度和模糊、进退场照 Vue `.modal-overlay` / `.modal-card` / `.dialog-card__*` 写进主题配方（`appearance.rs`）；宽度、危险口气和标题前的图标照各对话框的 Vue 模板和宽度类。截图对照下卡片的位置、宽度和分隔线在 1px 内。还剩的差异：
  - 卡片没有 Vue 的 1px 透明描边：内容整体上移 1px，卡片矮 2px。
  - 导出对话框的标题行矮约 2px：Vue 的 24px 关闭钮把那一行撑到 24，NanaUI 的关闭位不撑高标题行（确认框忙碌时藏起关闭位，正文不跳），最小行高按没有关闭钮的对话框取 Vue 正文的行盒 21.7。
  - 投影是主题的浮层投影 `0 14px 30px`，深色 45% 黑、浅色 28% 黑；Vue `.modal-card` 两个主题都是 `0 14px 40px` 45% 黑。卡片上下外缘的阴影比 Vue 收得快，浅色主题下也更淡。
  - 删除插件的确认框在 Vue 里是 Lilia `ConfirmDialog`（`UiDialog`：最高 76vh、`--radius-md`、没有分隔线、内边距 14/16/8），Nana 和别的对话框一样用 `.modal-card` 的配方；宽度、危险口气、标题前的警告三角和按钮照 Vue。
  - 建文件、新建文件夹、移动和三种导入在 Vue 里没有对话框（工具栏输入框、拖放、原生选择器）。Nana 的这几个对话框用 `.modal-card` 的宽度，标题前的图标按动作取：建文件 file-plus、新建文件夹 folder-plus、移动和导入 folder-open、ZIP 导入 archive。
  - 新建播放集的两个字段之间留 12，和别的对话框一样；Vue 的 `.playlist-dialog` 没写样式，两个字段贴在一起。
- 预览里的图片：照片和 Vue 的 `<img>` 一样按 EXIF 方向摆正。SVG 由 NanaUI 带着的 resvg 画成最长边 2048 的位图，再按 contain 铺进预览框（Vue 按显示尺寸画矢量）：预览框比 2048 个物理像素大时略软；SVG 里的文字用界面自带的 Noto Sans SC，不读系统字体。任一边超过 8192（宿主纹理上限）的图按比例缩到 8192 以内再显示。
- 二维码按 `qrurl` 重新编码，内容和 Vue 相同，但模块排布不同。
- 勾选框选中时是强调色底上的「✓」（Vue 是浅色底上强调色的小方块）。NanaUI 的勾用主题配方里「强调色上的字色」，浅底上看不见。
- 日志页的仓库筛选按最长的选项（`acceptance-repo`）定宽以后，1200×800 下外框 206.5，Vue 是 188；插件筛选只有短选项，下拉框停在最小宽 122，外框 182（Vue 180）。多出来的是字宽：Vue 字体栈第一项 Noto Sans SC 在对照机上没装，Edge 用 Segoe UI 画拉丁字母，`acceptance-repo` 约 108；Nana 自带 Noto Sans SC，同一串约 130。箭头（16）和内边距（0）和 Vue 的原生下拉框相当。
- 文档语言：照 Vue `index.html` 的 `lang="zh-CN"`，壳层挂树之前给文档声明应用语言 `zh-CN`（`view_host.rs` 的 `ShellView::mount`；真实窗口、测试 harness 和截图场景都从这里挂，测试 `every_mount_shapes_text_in_simplified_chinese`）。效果和 Chrome 用同一份字体画 `lang="zh-CN"` 一样（NanaUI `docs/reference/look.md`）：
  - 中文的标点按 NanaUI #211 挤压行首行尾和相邻的全角标点（`text-spacing-trim: normal`），换行按中文的避头尾规则。现有场景里没有相邻的全角标点，换行也没有变化（56 个场景的节点清单逐行相同）。
  - 拉丁文字和数字按简体中文挑 Noto Sans SC 自己的字形：拉丁文字里的数字（`track-01.mp3`、`2400000 B`、`v0.2.0`、`#3fa796`、`step: 2`……）不再换成默认语言系统的矮字形，和字母一样高，直引号升高。122 张截图因此有细小变化，都是这类数字变高，和 Vue 一致。只有数字和标点的一段（`0:00 / 0:00`、日期）本来就是原样的字形，等宽字体（文本预览）不受影响。

### 数据
- PDF 预览：Vue 用 pdf.js 照原样画（嵌入字体、图片、矢量）。Nana 换上渲染器以前只做到页数、页序和翻页对：按页树数页，每页只画内容流里的 Tj/TJ 文字（5×7 点阵，不解析字体编码，中文和多数现代 PDF 是乱码）或者扫描页的 JPEG，只画前 32 页；原来把文件里的每个流（字体、ToUnicode、对象流）都当成一页，第一页画不出来时翻页按钮跟着消失。
- 标签菜单没有仓库级标签组；智能文件夹的摘要行省略了。
- 浏览时生成缩略图：Vue 开 3 个并发，选中项和根目录的条目优先，每次读回目录（包括文件变化以后的静默重读）都把还没有缩略图的条目重排一遍。Nana 一次一条（后端在写锁里排队生成，并发不会更快，还多占任务线程，别的写操作也插不进来），选中项优先、再按列表从上往下；同一个目录里排过的（失败的、生成不了的）不重试，换了目录才重来。网易云歌曲和歌单目录的来源封面 Vue 在生成不了时用 `save + sourceUrl` 下载、存成自定义缩略图，Nana 还没有做（见 [API 设计](./api-design.md) 的 `thumbnails:ensure`）。
- `foreign-tool`（宿主没有内置页面的工具页）只画页头和说明。插件只能在清单里声明工具页，页面由宿主画，API Playground、文件导入和 Eagle 导入三个内置页面照旧（它们的插件改成了仅清单）。Vue 当时直接挂插件自己的组件；插件前端删掉以后，插件不能再自带页面。
- 插件清单声明的预览（`contributes.preview`）在 Vue 里要加载插件前端的 `dist/register.js`，由它 `registerPreview` 的 Vue 组件绘制。插件前端删掉以后合同里没有这一项了（见 [API 设计](./api-design.md)），Nana 也从来不登记这些贡献。随附插件（媒体、音频、文本、Office、压缩包、三维模型）声明的扩展名都由内置视图接手；只有第三方插件认得的扩展名照 Vue 没有预览插件时的样子，预览框只画缩略图或类型图标，不写字。原来给不能绘制的贡献写的「原生预览 · 名称 · 视图 id」随登记一起删掉。
- Vue 没有入口的设置卡已从设置页移除：缩略图缓存上限、默认播放器类型（`default_playlist_player_type_id`，不是设置页上的「音频播放」）、关闭行为、「保存应用设置」按钮，只为它们存在的消息和草稿也一并删掉。设置字段本身保留：缓存上限照旧校验和保存，默认播放器类型照旧读写，关闭行为照旧由关窗流程读取。主题改动后立即写入设置文件。
