# Nana 与 Vue 对照

原生壳层以 Vue 界面为参照，但目标是正确，不是逐像素复刻。取舍的优先级：

1. 功能、数据和状态正确：设置真正生效，交互结果正确，空、错、禁用、加载各状态都对。
2. 符合 `DESIGN.md` 的设计意图，并沿用 Vue 的结构层级和文案。
3. 像素细节。

Vue 的缺陷、死代码和意外的层叠效果不照抄，按设计意图实现，并记在本页。

## 对照方法

- Vue 侧：用 `@tauri-apps/api/mocks` 模拟 IPC，在无头 Edge（与 WebView2 同内核）里截图。场景数据与 Nana 验收场景同名。
- Nana 侧：`NANA_SCENES=… NANA_SIZES=1200x800,960x600 NANA_THEMES=light,dark cargo test -p momobako-nana --test scene_shots -- --nocapture`。场景定义在 `src-nana/src/shell/acceptance_*.rs`，输出 PNG 和节点清单。截图前先把视图量到尺寸后发回的消息（播放条宽、文件列表宽）归约几轮，截到的是稳定后的画面。
- 有仓库的场景都从 `acceptance_base.rs` 的共用底子起步，对应 Vue 夹具 `base()`：照产品启动依次送回资源库列表、同步、仓库摘要、首屏目录和侧栏的读取结果，侧栏计数、目录树和文件列表都由这些结果算出。场景要别的条目、目录树、播放集、播放器或仓库时改底子的字段，和 Vue 场景改 `scene.entries`、`scene.playlists` 一样。
- 两边逐场景出差异热图和差异像素比例。比例只用来发现问题，不作为通过标准。

## 全局取舍

**颜色合成。**
- NanaUI 在线性空间混合（见 NanaUI `docs/reference/text-engine.md`），Chromium 在 sRGB 空间混合。带透明度的主题角色（强调浅底、悬停底、浅红浅绿底）在 Nana 里更亮，深色主题下更明显。主题角色保留 NanaUI 的设计，不为对齐改动。
- 例外：Vue 用整块 `opacity` 盖在已知不透明底色上的地方（禁用态、色块外圈、播放条淡化），改用 `SemanticColorMix::new(前景, 底色, 比例)` 直接在 sRGB 通道混。
- 纯黑遮罩：线性空间里是把底色乘以 `1 - α`。要和 Vue 的 45% 黑一样暗，不透明度取 `linear_scrim_alpha(0.45) = 1 - 0.55^2.2 ≈ 0.732`。对话框的遮罩是主题的效果令牌 `modal_scrim`，`appearance.rs` 按这个换算写进去；背景模糊是 `modal_scrim_blur`，照 CSS 写 2。

**按钮。**
- Lilia 全局样式 `button, select { height: 32px }` 会压过组件自己声明的尺寸，例如 26px 的筛选芯片、日志芯片、适应/填充分段，以及 24px 的分组标题按钮。这种情况视为层叠缺陷，按组件声明的设计值画。没有声明尺寸的普通按钮和下拉照 32px 画。
- 侧栏行按声明的 28px 画（Vue 实际渲染为 32px），所以下面各组比 Vue 上移约 20px。
- 只写了裸类名、在 `src/styles` 里没有任何样式的按钮（`primary`、`ghost`、`ghost danger` 等），Vue 渲染成透明底、正文色。Nana 按 DESIGN.md 5.1 画：主操作用低饱和强调色，危险操作用低饱和红，普通操作透明。

**圆角。**
- 圆角半径基数来自设置（0–20，默认 8）。xs 到 xl 分别是基数的 0.5、0.75、1、1.25、1.5 倍。
- Vue 的 `--radius-2xl` 没有对应档位，按 2 倍基数的像素值画（`theme_map::radius_2xl`），或退到 Xl 档。
- 「平滑」圆角是主题的 `CornerShape::SQUIRCLE`（CSS `superellipse(2)`），「普通」是圆弧。

**关闭窗口。** 和 Vue/Tauri 一样直接退出，只有存在未保存修改时才先确认。

## 没照抄的 Vue 缺陷

### 壳层与侧栏
- 文件面板收的是全局 `error`：任何失败（定位失败、读素材详情失败、刷新文件夹树失败……）都把文件列表换成红色状态框，和侧栏状态区重复，列表也看不到了。Nana 的文件列表只显示文件操作自己的失败，别的失败只在侧栏状态区。
- 删除资源库、删除文件夹的选项卡片被全局 32px 高度压扁，标题和说明叠在一起。
- 智能文件夹对话框的最大高度是 72vh，800 高的窗口下底部「取消 / 创建」被裁掉。
- 启动日志时间用了未定义的 `--text-subtle`。
- 文件夹树的展开箭头底色盖住了树的引导线。
- 资源库切换按钮的无障碍名只有「资源库」，不含仓库名。
- 添加菜单的 160px 宽被 `.ctx-menu` 的最小宽度覆盖。
- 刷新文件夹树途中换了仓库，Vue 后半段的重读按当时的活动仓库读，会落到新仓库上；Nana 作废这一轮。

### 文件页
- 导入菜单用了未定义的 `--panel-bg`，退回到 `#15171a` 深色底，字看不清。
- 960×600 下面包屑「根目录」逐字竖排，分隔线压到卡片上。
- `.files-list` 的网格行被拉伸或挤压。
- 详情预览是透明底白图标，浅色主题下看不见。
- 文件卡 `overflow: hidden` 把导入菜单裁掉。
- 导出对话框缺少输出路径，已补上。
- 列表模式在 960 宽下标题列被压到 0、内容溢出卡片；Nana 给标题至少留 80px。

### 搜索与筛选
- 筛选芯片按设计值 26px 画；结果行高度按内容决定。
- 高级区的宽输入框填满格子（Vue 卡在 120px 宽，占位文字被截断）。
- 占位文字用弱化色（Vue 是浏览器默认的 `#757575`）。
- 手动加的颜色和形状始终有芯片，可以单独点掉。
- 搜索失败时显示真实错误，不再叠一个「等待搜索条件」。
- 搜索跑完没有命中时，空状态写「没有匹配的文件」和所在范围（全部资源库或当前资源库）；Vue 仍写「等待搜索条件」。

### 预览与播放
- 唱片按视口定尺寸，在预览框里溢出、被裁成方块，歌词栏也被裁掉。
- 播放请求被暂停打断时，Vue 把它当错误显示。
- 文本按字节截断时切开半个字符，留下替换符。
- 压缩包预览用了未定义变量，浅色主题下也是深色面板。
- 播放条的宽排版网格在窄栏里溢出，断点只看窗口宽度；Nana 按播放条自身宽度切换三行排版。
- 播放集条目标题被全局按钮样式居中。
- 自动播放失败后，图标仍显示「暂停」。
- 在 ASMR 资源库里打开音频预览，文件工作台和预览页上下同时出现，工作台里的播放条还显示「未选择播放内容」；Nana 只显示预览页。
- 文件预览里的音视频失败（读不出、认不出格式、解码失败），Vue 只在播放条第二行写一行弱色小字，预览框里照旧是唱片舞台或黑底。Nana 照 Vue 预览插件（`audioPreview.js`、`media-preview`）的失败浮层，在预览框里写红色标题「无法预览该音频」（视频是「无法预览该媒体」），下面一行原因，包括 Nana 自己的「没有原生解码器」和各格式的「解码失败」。播放条装不上同一个文件、写回的失败也这样显示。预览和播放条共用同一个解码，坏的 wav、mp3、flac、ogg 报它自己格式的原因，不再被说成没有解码器。

### 设置、插件与日志
- 日志追踪滚动的是 `.logs-workbench__list` 本身，但列表不定高（只有 `min-height: 360px`），实际不会滚动，记录一多页头和筛选就跟着整页滚走。Nana 按意图做：日志页主体不滚，页头、工具条和筛选固定，列表占满面板剩下的高度、自己滚动；追踪时跟随末尾，暂停时停在原位。列表不设 360 的最小高，窗口矮到放不下时列表先让出高度。
- 文件导入、Eagle 导入工具页的 `tool-page-shell` 类全仓库没有 CSS。
- 圆角滑杆用了 `appearance: none`，轨道不可见。
- 设置数据刷新成功后，旧的错误提示不会清掉；Nana 刷新成功会清掉。

## 已知差异

### 交互
- 右键子菜单点击展开（Vue 悬停展开）。应用层拿不到悬停事件。
- 所有对话框都响应 Escape、点外面和关闭位（处理中都不关）：删除资源库对话框在 Vue 里不响应 Escape，这里一致响应。
- 对话框打开时框架把焦点放进对话框（第一个可聚焦的控件，确认框是「取消」），关掉后焦点回到打开前的位置；Vue 不管焦点。
- 正在用输入法组合时，新的对话框等组合结束再打开（一激活就会拿走焦点、打断组合）。
- 同时打开的浮层只显示一层：关闭确认最先，其后是原来浮层槽位里的对话框、弹层和菜单，文件页的导出和文件对话框最后（原来画在主区里，压在浮层下面）。
- 点菜单外面关闭菜单时，这次点击不会穿透到下面的控件；右键别处只关菜单、不重新打开；滚动、缩放、失焦不会自动关菜单。
- 导入用应用内的路径对话框（Vue 用原生文件选择器）。
- 播放集条目从拖动柄和行的留白拖动排序；按在扩展名方块、标题、播放和移除上是点击。Vue 整行都能拖，在按钮上按下拖动也开始拖动。NanaUI 的 `ReorderList` 按下行就抓走指针，一行只能标一块不开始拖动的区域，见「NanaUI 缺口」。
- 框选只能选到已经建出来的卡片（视口加上下各 240px），选不到滚出视口很远的行。
- 瀑布流各列先按平均高度估算卡片高度，滚动中测到真实高度后，滚动条可能小幅跳动。
- 刷新文件夹树要同步整个仓库。Vue 在整轮刷新期间把文件列表换成「正在读取目录」；Nana 在同步和重读期间照常显示列表，进度写在侧栏状态区，最后重读目录时列表才显示读取中。刷新按钮除了 Vue 的「正在读目录」，在目录树自己读取时也转圈禁用。

### 外观
- 图标用 Tabler（Vue 用 Lucide），个别图形不同。
- 对话框统一用 NanaUI `Dialog` / `ConfirmDialog`（行为优先）。距顶 12vh、最高 72vh、`--radius-xl`、三段内边距和两条分隔线、遮罩的暗度和模糊、进退场照 Vue `.modal-overlay` / `.modal-card` / `.dialog-card__*` 写进主题配方（`appearance.rs`）；宽度、危险口气和标题前的图标照各对话框的 Vue 模板和宽度类。截图对照下卡片的位置、宽度和分隔线在 1px 内。还剩的差异：
  - 卡片没有 Vue 的 1px 透明描边：内容整体上移 1px，卡片矮 2px。
  - 导出对话框的标题行矮约 2px：Vue 的 24px 关闭钮把那一行撑到 24，NanaUI 的关闭位不撑高标题行（确认框忙碌时藏起关闭位，正文不跳），最小行高按没有关闭钮的对话框取 Vue 正文的行盒 21.7。
  - 投影是主题的浮层投影 `0 14px 30px` 45% 黑（Vue `0 14px 40px`），卡片上下外缘的阴影比 Vue 收得快。
  - 删除插件的确认框在 Vue 里是 Lilia `ConfirmDialog`（`UiDialog`：最高 76vh、`--radius-md`、没有分隔线、内边距 14/16/8），Nana 和别的对话框一样用 `.modal-card` 的配方；宽度、危险口气、标题前的警告三角和按钮照 Vue。
  - 建文件、新建文件夹、移动和三种导入在 Vue 里没有对话框（工具栏输入框、拖放、原生选择器）。Nana 的这几个对话框用 `.modal-card` 的宽度，标题前的图标按动作取：建文件 file-plus、新建文件夹 folder-plus、移动和导入 folder-open、ZIP 导入 archive。
  - 新建播放集的两个字段之间留 12，和别的对话框一样；Vue 的 `.playlist-dialog` 没写样式，两个字段贴在一起。
- 二维码按 `qrurl` 重新编码，内容和 Vue 相同，但模块排布不同。
- 勾选框选中时是强调色底上的「✓」（Vue 是浅色底上强调色的小方块）。NanaUI 的勾用主题配方里「强调色上的字色」，浅底上看不见。
- Select 不能按最长的选项定宽：仓库筛选框宽 180（Vue 是 188）。

### 数据
- 标签菜单没有仓库级标签组；智能文件夹的摘要行省略了。
- `foreign-tool`（第三方插件自己的工具页）只画页头和说明。Vue 在这里直接挂插件组件，原生壳层不运行插件的 Vue 组件。
- Vue 没有入口的设置卡已从设置页移除：缩略图缓存上限、默认播放器类型、关闭行为、「保存应用设置」按钮，只为它们存在的消息和草稿也一并删掉。设置字段本身保留：缓存上限照旧校验和保存，关闭行为照旧由关窗流程读取。主题改动后立即写入设置文件。

## NanaUI 缺口

| 缺口 | 现状 |
| --- | --- |
| Select、滑杆等没有可见标签的控件，没有声明式的无障碍名称 | 挂载后按字段标签补名字；上游修复中 |
| 固定定位盒自动高度时，百分比 `max-height` 被当成 0 | 上游已修；用到它的文件页自建对话框卡片改成 NanaUI `Dialog`，这处 `vh` 绕行随卡片删掉 |
| 网格自动行高按最窄内容测量，可折行的芯片把行撑高 | 插件区块改用横排；上游核实中 |
| IconButton 的默认方形尺寸盖掉显式布局 | 上游已修；任务弹层关闭钮删掉了 `square = None`，别的区域各自清理 |
| 框架自己关掉 Dialog 时不通知应用 | 上游已修：`DialogCloseRequested` 加 `DialogClosePolicy::requests_only()`，对话框框架只听请求、发关闭消息 |
| `DialogSize` 只有 420 / 520 / 600 / 680 / 1080 几档，不能给像素宽，也不能按窗口比例收 | 已补：`DialogSize::Width(长度)` 和 `capped(px, vw)`。各对话框照 Vue 的宽度类给 CSS 宽度 |
| 对话框标题没有危险口气（`ConfirmDialog.danger` 只改确认按钮） | 已补：`Dialog::danger` / `ConfirmDialog::danger`，标题取主题的危险色。借节点文字色的写法已删 |
| 对话框没有头部下分隔线、底栏上分隔线，头部、正文、底栏的内边距不能配 | 已补：`DialogRecipe` 的三段内边距、分隔线和按钮间距 |
| 对话框距顶固定 90px，不能按视口比例（12vh）放；最大高 76% 不能配 | 已补：`DialogRecipe::top` / `max_height` 按视口比例给 |
| 遮罩颜色写死 45% 黑，没有主题令牌，也没有背景模糊 | 已补：`EffectTokens::modal_scrim`、`modal_scrim_blur` 和换算 `linear_scrim_alpha`。`appearance.rs` 照 Vue 写进主题，补色层已删 |
| 背景模糊的着色器取 `半径 / 3` 作高斯标准差，CSS `blur(Npx)` 的 N 就是标准差，同样写 2px 只有浏览器约三分之一的模糊；7 个样本的间距随半径变大，半径大了有条纹 | 已修：`blur(r)` 的 r 就是 CSS 的高斯标准差，核读到三倍标准差内的每个纹素。遮罩模糊照 CSS 写 2 |
| 对话框头部没有图标位 | 已补：标题图标槽 `title_icon`，图标格、关闭位、间距和最小行高归 `DialogRecipe` |
| 对话框卡面圆角固定 `Md` 档 | 已补：`DialogRecipe::radius` |
| 对话框开场只有淡入，没有卡片位移和缩放；表面开合动效不看「减少动态效果」 | 已补：`DialogRecipe::motion`（`DialogMotion`），减少动态效果时直接开合 |
| `activate_overlay` 要求宿主已在树里；视图层没有「挂进树时」的钩子，也没有声明式的打开状态 | 已补：`.open` / `.model` 声明开合，宿主做的开合发 `DialogToggled`。对话框常驻在宿主下靠 `open` 开合，换下的放完退场才卸 |
| `ReorderList` 按下行就抓走指针，行里的按钮收不到点击；一行只能用 `.tools(节点)` 标一块不开始拖动的区域 | 播放集条目把扩展名方块、标题、播放和移除包成一段登记成 `tools`，从拖动柄和行的留白拖动。需要一行标多块，或者按下按钮时不开始拖动 |
| 应用层没有悬停事件 | 子菜单改为点击展开 |
| 滚动范围按全部后代的盒子合并，不在里层的滚动区或裁剪盒处停下 | 滚动区里不再套滚动区：日志列表自己滚，日志页主体改成不滚的裁剪盒（`route_home::home_fixed`）。需要滚动范围只算到最近的裁剪祖先 |
| `RadiusTier` 没有 2xl 档 | 用 2 倍基数的像素值 |
| 线性空间混合 | 设计如此，见上文「颜色合成」 |
